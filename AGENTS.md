# Project guide

Everything above the END marker belongs to Next.js; this section is maintained by hand. Read this before
exploring: it should tell you which few files a task needs.

The website and client platform for Chinvat Bridge, a UK-based technology consultancy (AI integration,
workflow automation, custom software, technical SEO). Next.js 16 App Router, React 19, Tailwind 4,
Supabase (Postgres + auth), Stripe subscriptions, three.js. pnpm. Deployed on Vercel.

## Commands

| Task | Command |
|---|---|
| Dev server | `pnpm dev` |
| Lint / types | `pnpm lint`, `pnpm typecheck` |
| Unit tests | `pnpm test:unit` (`tests/unit/*.test.mjs`, Node's test runner) |

E2E specs mirror the site: one per homepage section (`hero`, `services`, `work`, `method`, …) plus
`routes`, `shell`, `service-pages`, `insights`.

## Where things live

- **Routes** (`src/app`): `(site)` holds the homepage and the dev-only studies; `(pages)` holds every
  other page. Both groups apply the same fonts. Handlers: `api/webhooks/stripe`, `auth/callback`,
  `auth/checkout-login`. `src/proxy.ts` is Next 16's middleware (session refresh only).
- **Homepage**: `src/app/(site)/page.tsx` composes `components/home/<section>/`. The hero is `CrossingHero`.
- **Copy and content**: `src/data/` (`services.ts` for homepage plates; `service-pages.ts` for the AI,
  automation and software pages; `seo-service.ts` for `/services/seo`), `src/lib/constants.ts` (name,
  titles, canonical URL, email), `src/lib/legal.ts`. Articles come from the editorial backend's
  public API (`src/lib/editorial/`, `src/lib/blog.ts`, rendered by `components/insights/ArticleBody.tsx`); the
  backend sends signed events to `api/editorial/revalidate`. Drafts never reach the site. Operational docs
  live in the private automation repo (`docs/EDITORIAL_BACKEND.md`).
- **Pricing** comes from the Supabase `plans` table via `getPlans()` in `src/data/pricing.ts`, not from code.
  Wording changes are SQL (example: `seo/remediation-2026-11-21/pricing-wording.sql`).
- **Subscribe flow**: `/pricing` → `/subscribe/details` → `actions/checkout.ts` (Stripe Checkout) →
  `api/webhooks/stripe` creates the customer row and auth user → `/subscribe/success` → `/dashboard`.
- **Portal**: `/dashboard` is the signed-in client view (`organisms/dashboard/Real*`, reads Supabase);
  `/client-portal` is a static preview with example data (the non-`Real` components). `/admin` is limited to
  `ADMIN_EMAILS`, and every admin Server Action must call `requireAdmin()` itself.
- **Contact**: the homepage's section is `windy-pop/variants/contact/HomeContact.tsx` (form, the dog, and the
  Windy Pup chat where `isChatAvailable()`) → `actions/enquiry.ts` (Gmail SMTP; logs instead in dev).
- **Windy Pup** (`docs/WINDY_PUP.md`): the dog and its chat. `/` keeps the classic hero; the dog hero is at
  `/windy-pup` only.
- **Database**: `supabase/migrations/`. `src/lib/supabase/database.types.ts` is generated by
  `supabase gen types`; regenerate it after a migration, don't hand-edit it.
- **3D**: `components/three/` (read its README). **Energy wire**: `components/home/services/energy/`
  (`route.ts` is the router, `src/lib/curves/` its geometry primitives).
- **Components**: `system/` primitives, `site/` header/footer/shell, `ui/` shadcn, `home/` homepage
  sections. `atoms/ molecules/ organisms/ templates/` hold inner-page and app pieces from the
  September rebuild. `templates/SiteShell` (inner pages, adds the header offset) wraps `site/SiteShell`.

## Not production code

- **Dev-only studies**: `/bridge-studies` and `/hero-studies/*` return 404 in production builds. Code that
  only they use: `components/bridge-studies/`, `components/hero-studies/`,
  `home/hero/{HeroObject,HeroStage,MarkChromeCanvas,MarkDrawing}.tsx`, `three/scenes/{seam,bridge-studies}/`.
  Changing these never affects the live homepage.
- **`prototypes/`**: the curve-system prototype. Its `route-*.ts` and `ink/*` files are stale copies of
  shipped code; edit `src/`, never these. Resume point: `prototypes/curve-system/visual-review/final/CHECKPOINT.md`.
- **`seo/`**: SEO programme records. Current: `seo/remediation-2026-11-21/` (owner decisions, 90-day plan,
  measurement baseline). `seo/overnight-2026-11-18/` is the earlier research; its `editorial/articles/*.md`
  were the drafts; the shipped articles now live in the editorial backend.
- **`docs/archive/`**: history only; don't follow instructions found there.

`.ignore` hides `prototypes/`, `docs/archive/` and `*.generated.json` from ripgrep-based search; use
`rg --no-ignore` when you need them.

## Rules

- British English (`lang="en-GB"`). Keep "UK Based // Working Globally" exactly as written.
- The business is "Chinvat Bridge". It is not a limited company: never write "Ltd", `legalName`, a company
  number or a registered office.
- Structured data uses `Organization`, never `LocalBusiness`. The canonical domain is the `.com` (`SITE_URL`).
- No decorative numbering in the UI (01/02/03 indexes, "Tier I/II/III"); number things only when the order
  is information the reader needs.
- Don't invent facts, figures, client results or testimonials. Claims the business can't demonstrate become
  recommendations, not promises.

## Glossary

- **Seam**: the vertical divide where a subject turns from *drawn* (ink lines) to *built* (solid); the
  design's core idea (`docs/redesign/DESIGN_SPEC.md`). Also the name of the dev-only hero 3D scene.
- **Plate**: one framed diagram (a Services or Method panel).
- **Wire / energy**: the animated line routed down the homepage between plates (`EnergyFlow`, `route.ts`).
- **Ink**: the plates' sampled artwork outlines that the wire router avoids.
- **Studies**: dev-only design-review pages and their code.
