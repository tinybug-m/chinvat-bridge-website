# Security findings and remediation — 22 November 2026

Scope: this website (`chinvat-bridge-website`) and the SEO automation (`chinvat-seo-automation`).
The audit found no exposed credentials in either repository, in their full Git history, in the
public GitHub mirror, or in the live site's client bundles, so nothing needs rotating.

All fixes below are in the working tree and not yet committed. Two Supabase migrations must be
applied **before** this code is deployed (see "Deployment order").

## Deployment order

1. Apply `supabase/migrations/20261122120000_checkout_login_redemptions.sql` and `supabase/migrations/20261122121000_rate_limit_buckets.sql`, for example with `supabase db push`. Both were validated on PostgreSQL 17 by `bash tests/db/security-migrations.test.sh`.
2. Optionally set `RATE_LIMIT_SECRET` in Vercel (Production). Without it, the rate-limit keys are derived from the service-role key.
3. Deploy the code.

If the code goes out before the migrations, it fails safe. Automatic post-checkout sign-in returns "unavailable" and the customer requests an emailed link. Rate limiting falls back to the per-instance limit.
